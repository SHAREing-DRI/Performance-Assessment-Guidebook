\section{GPU performance}
\label{section:high-level:gpu}

\begin{summary}
 We consider a code to make efficient use of the GPUs if it 
 achieves more than 80\% of the theoretical peak performance of the GPU. We consider
 a code to make reasonable use of the GPUs if it achieves more than 60\%. 
\end{summary}

\begin{wip}
    This section is still in its early stages of development, but the key takeaway is that: for a code with GPU offloading we simply want to measure the GPU work rate i.e. FLOPS/s.
\end{wip}

Similarly to the core performance, the GPU analysis examines how efficiently your code harnesses the GPU.
Our analysis evaluates how effectively your implementation takes advantage of the extreme parallelism of the GPU's capabilities.

To capture GPU behaviour at this high level, we want to measure the peak performance relative to the hardware's capabilities.
Similarly to core performance, the tools can draw us towards more detailed metrics and models, but to minimise distractions and clarify our analysis we restrict this rubric to the peak performance percentage.

We want to ensure that the data we collect about the code is a reliable and accurate representation of the performance of the code on a single GPU. To this end, we require that the code is built for the specific GPU architecture, and that the benchmark is larger than the GPU cache - see assessment crime \ref{assessmentcrime-cache-fit}. You should measure the memory footprint of your benchmark on the GPU in order to verify that the benchmark is large enough.

\begin{assessmentcrime}
 We study a code that is not built against the latest version of CUDA/HIP/etc. supported by the hardware
\end{assessmentcrime}

For example, if you are working with an NVidia H200 GPU, which supports CUDA compute capability 9.0, you must use a cuda toolkit version of at least 11.8 and specify \verb|-code=sm_90|.

\begin{instructions}{Nvidia Nsight}

Nvidia Nsight Compute provides tools to collect specific metrics during program runtime.
In order to calculate the FLOPS/s, we need to collect metrics of the total number of floating point operations executed. These are in the format
\verb|sm__sass_thread_inst_executed_op_METRIC_pred_on.sum|,
where \verb|METRIC| is \verb|dfma|, \verb|dadd|, \verb|dmul|, \verb|ffma|, \verb|fadd|, \verb|fmul|, \verb|hfma|, \verb|hadd|, and \verb|hmul|.

We can request this set of metrics using a regex, and so profile the program:
\begin{verbatim}
ncu --metrics "regex:^sm_.*d_op_(d|f[^p]|h).*\\.sum$" --csv \
    --log-file out.csv ./code
\end{verbatim}



 % Regex to paste into GUI to filter to these
 % ^smsp.*inst_executed_op_(d|f)(add|mul|fma)|duration\.sum|cycles_elapsed\.max
 
\end{instructions}

We also need to measure the execution time of the program without the profiler attached - here we make the assumption that the number of operations executed is the same in every run regardless of execution time.

% Rule of thumb this?
Where multiple different precisions are used, they will run at different rates on the hardware, but we need a single number to compare against the theoretical performance of the GPU. We therefore count each double-precision instruction (those beginning with \verb|d|) for double the number of operations, and each half-precision instruction (those beginning with \verb|h|) for half the number of operations. Additionally, because each \verb|fma| (fused multiply-add) does two operations in one instruction, we further double the number of operations these instructions count for.

We finally calculate the observed work rate:
\begin{equation}
    R_{\texttt{observed,FLOPS/s}} = \frac{\sum N_\texttt{opers}}{T_\texttt{exec}}
\end{equation}

\subsection{Evaluation}

\begin{performancemetric}
 The percentage of the theoretical maximum GPU FLOPS/s throughput achieved by the computational kernels. This may also be referred to as GPU peak-performance-percentage.
\end{performancemetric}

We calculate the peak performance ratio as
\begin{equation}
    C_\texttt{GPU} = \frac{R_\texttt{observed}}{R_\texttt{theoretical}}
\end{equation}

\begin{center}
 \begin{tabular}{p{0.34\textwidth}p{0.62\textwidth}}
  GPU peak performance ratio & Description \\
  \hline
  $C_{\text{GPU}} \geq 0.8$
   & \cellcolor{green!25} GPU compute performance is good
  \\
  $0.6 \leq C_{\text{GPU}} < 0.8$
   & \cellcolor{yellow!25} GPU compute performance is not particularly good. This could become a significant issue with other GPUs including newer generations.
  \\
  $C_{\text{GPU}} < 0.6$
   & \cellcolor{red!25} GPU compute performance is poor.
 \end{tabular}
\end{center}
