%Inefficient data transfers between host and device can lead to significant waiting times, similar in principle to communication inefficiencies with MPI codes. The worst offending codes rely on frequent data transfers back-and-forth between host and device.
%Therefore, we would like to categories the ratio of GPU compute time to data transfer time. Frequent data transfers can in some cases be a product of naive porting to GPU. Many GPU ported codes rely on some form of `data transfer minimisation', i.e., the simulation is configured on the CPU until the code hits a the computationally intensive kernel for which the data is transferred onto the GPU allowing for effective use of the GPU's comptational advantages. Then, the data is transferred back to the CPU to finalise the simulation or deal with some level of I/O. In practice this model is a simplification, and indeed some algorithms may not fit well into this design pattern. In which case the developer may not have considered how their algorithm will rely on considerable data transfers and therefore the outcome of a performance assessment could imply an algorithmic redesign to move more of the processing onto the GPU.
